# Restaurant Smart POS — Mobile Waiter PWA Deployment Guide

This guide details the architecture, deployment, and operational workflows for deploying the **Mobile Waiter Progressive Web Application (PWA)** to staff smartphones and tablets (iOS and Android).

---

## 1. Architecture & Capabilities

The Mobile Waiter application is built directly into the unified Restaurant Smart POS production codebase as an installable Progressive Web App (PWA).

- **Production URL**: `https://prismhut-org.vercel.app`
- **Backend API**: `https://prismhut-org.onrender.com/api/v1`
- **Supported Platforms**:
  - iOS (Safari 15+ via "Add to Home Screen" Web Clip)
  - Android (Chrome, Edge, Samsung Internet via native WebAPK install prompt)
  - Desktop & Tablets (Chrome / Safari / Edge standalone display)
- **Display Mode**: Full-screen standalone (`display: standalone`) with custom orange brand theme (`#ea580c`) and dark-slate title bar.

---

## 2. Security & Data Protection Policies

To ensure strict compliance with restaurant data privacy and PCI-DSS best practices:

1. **Zero Sensitive Cache in Service Worker**:
   - The Service Worker cache only stores static assets (HTML, JavaScript bundles, CSS stylesheets, Google fonts, and restaurant icons/logos).
   - All API endpoints (`/api/*`) and WebSocket channels (`/socket.io/*`) are **strictly excluded** from CacheStorage (`navigateFallbackDenylist`).
   - Customer information, credit card tokens, orders, and payment records are never persisted in unencrypted browser cache.
2. **Staff Role Isolation (RBAC)**:
   - Waiter accounts (`role: 'WAITER'`) can view floor tables, browse menu items, and create new orders (`POST /api/v1/orders`).
   - Waiter accounts are strictly forbidden from modifying restaurant settings (`403 FORBIDDEN`), modifying menu pricing (`403 FORBIDDEN`), accessing financial sales reports (`403 FORBIDDEN`), creating staff accounts (`403 FORBIDDEN`), and settling bills at the cashier (`403 FORBIDDEN`).
3. **Idempotency Safeguard**:
   - Every order submission generated by the Waiter PWA transmits a unique `x-idempotency-key` (UUIDv4) header and payload.
   - If a waiter experiences an intermittent mobile network disconnection and taps "Send to Kitchen" repeatedly, the backend recognizes the duplicate key and returns the existing order record without creating duplicate kitchen tickets or double charges.

## 3. Device Installation Instructions

### 3.1 Android Devices (Chrome / Edge / Samsung Internet)
1. Open Google Chrome on the Android device.
2. Navigate to `https://prismhut-org.vercel.app`.
3. Log in with the assigned Waiter credentials (e.g., `waiter` / `password123`).
4. Click the orange **"Install Waiter App"** button located in the top navigation bar, OR tap Chrome's 3-dot menu and select **"Install app"** (or **"Add to Home Screen"**).
5. Confirm the installation prompt.
6. The app icon will appear on the Android home screen and app drawer as **"SmartPOS"**. Launching it opens a clean, full-screen native app experience without browser URL bars.

### 3.2 Apple iOS Devices (iPhone & iPad on Safari)
1. Open **Safari** on the iPhone or iPad (PWA installation requires Safari on iOS).
2. Navigate to `https://prismhut-org.vercel.app`.
3. Log in with the assigned Waiter credentials.
4. Tap the **"Install iOS App"** button in the header (or directly tap the **Share** button in the Safari bottom toolbar).
5. In the Safari Share sheet, scroll down and select **"Add to Home Screen"**.
6. Confirm the app title **"SmartPOS"** and tap **Add** in the top-right corner.
7. The Restaurant Smart POS icon will appear on the iOS home screen with the custom orange app icon.

## 4. Mobile Waiter Operating Workflow

1. **Table Selection**:
   - Tap **Table Floor** from the navigation.
   - Tap any table card (e.g. Table 01) to view status or open a new order ticket.
2. **Taking Orders**:
   - Filter menu items by Category (Appetizers, Mains, Beverages, Desserts) or Department (Kitchen vs. Bar).
   - Tap dishes to increment quantities, add custom cooking notes (e.g., "Medium rare, dressing on the side"), and review real-time subtotal/tax calculations.
3. **Submitting to Kitchen / Bar**:
   - Tap **Send Order (Fire KOT/BOT)**.
   - The order is transmitted with an automatic idempotency key.
   - Kitchen Display System (KDS) receives the KOT ticket instantly via real-time WebSocket, and Bar Display System (BDS) receives drink items simultaneously.
4. **Offline Handling**:
   - If the handheld device drops Wi-Fi momentarily while walking into a cold storage or patio area, the PWA displays an unobtrusive orange **"Offline Mode"** status badge.
   - The app automatically reconnects and re-synchronizes when Wi-Fi signal is re-established.
